// THREE REASONS

The repo remembers why.

Capture Domain Learnings, Learned Failures, decisions, and deferred work — with the reasoning behind them.

A shared, version-controlled brain across sessions, teammates, and even different vendors.

3

Local by default. Just files + two open-source MCP servers. Yours, in your repo, in your control.

// HOW SALVOR WORKS

Hub & Spoke

CLAUDE.md is the canonical hub; component spokes load only what you're working on.

Two-Tier Memory

L1 is a concise current-state cache. L2 preserves deep reasoning and recovery history.

3 User-Gated Triggers

Continued Learning → Domain Learning or Decision; Learned Failure; Deferred TODO.

Governed, Versioned Why

RULES.md §0 requires per-component VERSION.md history, memory, and spokes to stay synced.

Serena + GitNexus

Understand code. Analyze impact.

.salvor/ is the namespaced brain: L1/L2 state, DOMAIN_REF.md, infrastructure, deferred work, postmortems, .salvor/domain-learnings/, and .salvor/decisions/ for durable design rationale.

Every save is explicit. For a finding, the agent asks: Save this as a domain learning? (yes/no)

// THE SALVOR LOOP

Every request makes the next one smarter.

The shared brain supplies context before the work, then receives user-approved knowledge and rationale after it.

// USE SALVOR

>_

Any vendor: paste the prompt

PRIMARY PATH

Multivendor out of the box: CLAUDE.md is the canonical hub, with thin AGENTS.md and GEMINI.md entrypoints generated by default. There is no vendor to choose.

  1. Install Serena and GitNexus (see README).
  2. Open your LLM CLI in the project.
  3. Paste SETUP_PROMPT.md and answer the setup questions.
  4. Salvor creates the canonical hub, both vendor pointers, and the .salvor/ brain.
  5. Commit the scaffold. Run gitnexus analyze.
  6. You're done — your repo now has a memory.
